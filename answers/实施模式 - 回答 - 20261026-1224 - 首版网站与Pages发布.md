## 4. 具体改动区域

### 4.1 数据

- 14 条资源全部迁移到 JSON，id 唯一。
- 拆开 `verification.status`（家长实测 / 自动化测试 / 开发者声明 / 待验证 / 有异常记录）与 `familyPreference`（家庭喜欢 / 兴趣一般 / 未特别反馈）。
- 入口类型四选一：`play_web` / `store` / `source` / `official_info`。
- 中文启蒙、英文启蒙必须有 `learningFocus`；英文内容不会自动归入英文启蒙。
- Lucas：精选、家庭喜欢、商店入口、官方商店 URL。
- Momo、Tiny Dino、BabySmash：观察层；BabySmash 偏好如实为“兴趣一般”。
- 所有价格使用“开发者称免费 / 免费信息待核对 / 价格未确认”，不把未核实的免费范围写成事实。

### 4.2 页面

- 桌面：232px 侧边栏 + 右侧横向资源列表，保留 B 型结构、奶油白 / 薄荷绿。
- 手机：分类横向置顶，筛选为可关闭抽屉（遮罩 / Esc / 关闭按钮）。
- 保留搜索、分类、平台、内容语言、验证状态筛选，精选 / 中文优先 / 名称排序，列表 / 宫格，双语切换，详情弹窗。
- 新增三档分层徽章、四类入口按钮、异常列表、开发者标称年龄、家长建议、价格说明。
- 收录说明与关于本站弹窗；手机端可从抽屉进入。
- 插画为原创分类示意图，明确不是官方封面。

### 4.3 数据链

- `core.mjs` 统一筛选、排序、语言规则、入口标签。
- `validate.mjs` 校验字段、双语、URL 协议、入口类型、异常记录、Lucas / BabySmash 编辑规则、14 条数量。
- `sync-readme.mjs` 用同一数据生成 README 资源表；`--check` 在测试中拦截漂移。
- `e2e_check.py` 从真实 DOM 反查 14 条 id、按钮语义、链接、状态和布局。

## 5. 为什么这样改

- **单一事实源**：审计已经指出内嵌 `GAMES` 容易漂移；只有一份 JSON 才能让网站、README 和测试同步。
- **证据与偏好分离**：原 `status` 混轴会把“能运行”当成“孩子喜欢”。拆开后页面可以同时显示“自动化测试”和“未特别反馈”。
- **入口语义优先**：源码和商店不是直接可玩，按钮必须说清楚；否则家长点进去会以为本站坏了。
- **保留 B 型**：任务单明确不重新设计，因此只换数据与视觉 token，不换信息架构。
- **真实状态**：第三方声音没有复测，就写“待验证 / 有异常记录”，不写“已通过”。
